# ALT Magnifier

按住 <kbd>Alt</kbd> + 滚轮，把网页**当成一张图片整体放大**：鼠标指着的那一行字**钉在原地**，
周围内容向外扩张。放大过程**不重排、不改布局、元素位置零漂移**。

- 目标浏览器：**Microsoft Edge**（Chromium 内核，Chrome / Brave / Vivaldi 通用）
- 清单版本：Manifest V3，权限只有 `storage` + `scripting`，没有后台常驻、没有网络请求、不收集任何数据
- 平时零成本：不按 <kbd>Alt</kbd> 时只有两个 capture 监听器，非 Alt 立即返回，不写一个样式、不建一个 DOM

## 一、它和「浏览器自带缩放」有什么不同

| | 浏览器缩放（Ctrl +） | CSS `zoom` | **本扩展（transform）** |
|---|---|---|---|
| 触发重排 | 会 | 会 | **不会** |
| `window.innerWidth` / `vw` / `vh` | 变 | 变 | **不变** |
| 媒体查询断点 | 会重算 | 会重算 | **不重算** |
| 长文本折行 | 会重新折行 | 会 | **不会，字形相对位置完全不变** |
| 网站能察觉自己被放大 | 能 | 能 | **不能** |
| fixed 顶栏 | 永远钉在屏幕顶端 | 同 | **成为画面的一部分，随画面滚走** |

「网站察觉不到」是关键：B站、知乎这类重 JS 站点一旦发现视口变化就会重排布局，
元素立刻「散架」——这正是很多同类插件在 B站上失败的原因。

## 二、安装（30 秒）

1. 打开 `edge://extensions/`
2. 左下角打开 **开发人员模式**
3. 点 **加载解压缩的扩展**，选择本目录（含 `manifest.json` 的那一层）
4. 如果要测本地文件（`test/test-page.html` 直接双击打开），在该扩展的详情页里
   打开 **允许访问文件 URL**
5. 建议把扩展固定到工具栏，方便点开设置

升级/改代码后：在 `edge://extensions/` 点该扩展的 **重新加载** 按钮即可，已打开的页面不用刷新。

装好后工具栏上会有一个蓝色放大镜图标，**点它**会弹出控制面板（开关、倍率、触发键、测试页入口、一键自检）。

## 三、装不上 / 按 Alt 没反应？按这个顺序排

| 症状 | 原因 | 处理 |
|---|---|---|
| `edge://extensions` 里卡片是**灰色、点不开** | 清单缺 `action`（≤ v1.0.0 确实缺，v1.1.0 已修）；或加载的是子目录 | 确认选的目录里**直接**能看到 `manifest.json`；点该扩展的**重新加载**；仍不行就删掉重新加载 |
| 页面照常显示，**按 Alt 完全没反应** | 内容脚本没注入。首要原因：`file://` 页面默认不允许扩展访问 | 扩展详情页打开 **允许访问文件 URL**；或改用 `python -m http.server 8123` 后走 `http://localhost:8123/...` |
| 只有 `file://` 不行，`http://` 可以 | 同上，文件访问权限没开 | 同上 |
| 某些网站不行 | 命中站点规则，或该站把滚轮事件吃掉了 | 检查设置页的**站点规则**；把「调试日志」打开看控制台 |
| 面板显示「未检测到扩展」 | 扩展没启用 / 没重新加载 / 本页无权限 | 见上面三行 |
| Console 有红色 `Uncaught` 报错 | 我的代码问题 | 把红字原文发我，能直接定位到行 |

最快的自检方式：点工具栏图标 → 面板会自己检查「是否启用」和「是否有 file:// 权限」，并在底部给出 **运行自检**（纯计算，不需要鼠标）。

### 两条注入通道（v1.2.0）

声明式内容脚本（manifest 里的 `content_scripts`）是主路径：它在 `document_start` 就位、零延迟。
但 Edge 上出现过「清单、权限、开关都正常，声明式内容脚本就是不执行」的情况，所以加了一条**兜底通道**：

1. 后台在扩展启动、安装、以及每个标签页加载完成时，用 `chrome.scripting.executeScript` 主动确认引擎是否存活；
2. 只有声明式注入没生效时才补注入（引擎里有幂等守卫，重复注入不会重复绑事件）；
3. **打开工具栏面板时，会对当前标签页强制做一次确认**，并把结果用人话写出来：
   - `✓ 引擎已就绪` —— 可以用了
   - `✗ 注入被浏览器拒绝：<浏览器原文>` —— 这里会把 Edge 的原始报错原样显示，
     它通常直接指出原因（企业策略 / 页面受限 / 权限不足）。把这句话发我即可定位。

这也是为什么 v1.2.0 多了一个 `scripting` 权限。它不产生额外的权限警告，
而且站点访问权限本来就已经是「在所有站点上」。

## 四、怎么用

| 操作 | 效果 |
|---|---|
| 按住 <kbd>Alt</kbd> + 滚轮 | 以鼠标指针为锚点放大 / 缩小（默认向下滚 = 放大） |
| 松开 <kbd>Alt</kbd> | 默认 600ms 后自动还原，观感上仍停在你刚看的那一段 |
| <kbd>Esc</kbd> | 立刻还原，保留你放大后滚到的位置 |
| <kbd>Alt</kbd> + <kbd>0</kbd> | 回到**按下 Alt 时**的原地 |
| 右键扩展图标 → 选项 | 设置页（也支持 Alt+滚轮，可当场试） |

默认倍率范围 **1–32 倍**，上限/下限/步长/触发键都能在设置页里改（改完立即对所有已打开标签页生效）。

## 五、两分钟验收清单

### 1. 核心手感（最重要，30 秒）

1. 随便打开一个长文页面（维基百科、知乎、B站专栏都行）
2. 鼠标**停在某一个字上**，按住 <kbd>Alt</kbd> 向下滚几格
3. **那个字必须一动不动**，只有它周围的内容向外扩张
4. 松开 <kbd>Alt</kbd>：画面落回，位置对得上

### 2. 自动漂移检测（不需要靠眼睛）

打开 `test/test-page.html`（页面右下角有一个检测面板）：

```text
按住 Alt 滚轮放大到 4 倍左右 → 松开 Alt → 面板自动出报告
```

报告里会给出**实测倍率**和**位移清单**（单位：像素）。判定用的是几何恒等式：

```
若整页真的绕视口锚点 a 缩放 k 倍，则 p' = k·p + c 对**所有**元素成立。
脚本用相距最远的一对参考点反解出 (k, c)，再逐元素算残差 —— 残差就是位移。
```

想要更严格的独立取证，点面板上的 **载入扩展级检测**（或给网址加 `?magDiag=1`），
它会把检测脚本注入到**扩展的隔离世界**里跑一遍，页面自身无法伪造读数。

### 3. 命令行自检（可选，vibe check）

```bash
node tools/test-math.mjs       # 16 项核心数学断言：零漂移、倍率钳制、边界钳制
node tools/test-browser.mjs    # 端到端：启动无头 Edge + 真实 Alt/滚轮 输入事件
```

设置页里也有一个 **运行自检** 按钮，点一下就地跑同一批断言。

## 六、测试页覆盖的边界情况

`test/test-page.html` 里每个区域都对应一类容易出错的场景：

| 区域 | 验证什么 |
|---|---|
| 1. 定点文字 + 100px 量尺 + 4 个 60×60 定标方块 | 字号相对位置不变；放大 k 倍后尺寸精确变成 60k×60k |
| 2. `background-attachment: fixed` 大色块 | 那类「大糊背景」是否与边框严丝合缝（关掉设置里的修复开关可复现错位） |
| 3. 内嵌滚动容器 | 容器内部与外层比例一致 |
| 4. iframe（含内部 fixed 条） | 跨文档缩放是否同步，不会出现「里面比外面大」 |
| 5. canvas（每帧重绘）+ SVG | 位图/矢量在放大时是否清晰、不撕裂 |
| 6. 表格 / 列表 | 项目符号、表格线是否对齐 |
| 7. 长文 | 鼠标不动连滚 30 格，检验**累计误差**（实现有误差累积时，字会慢慢爬走） |

## 七、已知限制（说在前面，不藏）

1. **单击 <kbd>Alt</kbd>（不滚轮）仍会点亮 Edge 的「设置及其他」菜单。**
   这是浏览器级 UI，网页层拦不住（内容脚本不能阻止浏览器 chrome 的默认行为）。
   它不影响功能：松手菜单就散，滚轮照样能用。想彻底躲开，可在设置页把触发键换成
   <kbd>Ctrl</kbd> / <kbd>Shift</kbd> / <kbd>Win</kbd>（注意 Ctrl 会与浏览器缩放冲突）。
2. **`fixed` / `sticky` 元素会变成画面的一部分，随画面一起滚走。**
   这是「像放大图片」的必然结果：CSS 规定任何 `transform` 都会为后代创建新的包含块，
   `position: fixed` 的参照物从「浏览器窗口」变成了「这块被缩放、会移动的画布」。
   浏览器自带缩放之所以能钉住顶栏，正是因为它不创建新的包含块——代价就是必须重排。
   如果你确实想要顶栏钉住，alt 方案（`zoom`）会重新引入重排与断点重算，不建议。
3. **放大后鼠标滚轮只做缩放，不做平移。** 大范围移动请拖滚动条。
   如需要滚动条对齐，注意放大后滚动条位置与内容位置是线性对应的。
4. **32 倍是硬上限。** 再高会让滚动范围膨胀到 `页面高度 × 倍率`（几十万像素），
   合成层显存和滚动精度都会开始出问题。设置页的上限被钳制在 32。
5. **站点自己的 JS 若用 `getBoundingClientRect()` 算位置再写回布局属性**（拖拽跟随、
   进度条把手、自定义滚动条），仍可能出现偏移——因为视觉坐标被当成了布局坐标。
   本扩展已尽力避免触发它（不派发任何事件、不改视口相关属性），但无法阻止站点自己
   在滚动时重算。遇到这类页面用设置页的**站点黑名单**把它排除即可。
6. **浏览器自身缩放（<kbd>Ctrl</kbd>+滚轮 / Ctrl 加号）会让本扩展立即退出**，避免两套缩放叠加。
7. 无头 / 自动化环境下有坑：**正式版 Chrome 137+ 会忽略 `--load-extension`**
   （本地未打包扩展被安全策略挡住），Edge 154 仍然接受，所以 `tools/test-browser.mjs`
   默认优先使用 Edge。这条与扩展本身无关，见 [SeleniumHQ/selenium#16540](https://github.com/SeleniumHQ/selenium/issues/16540)。

## 九、原理与实现要点

### 唯一改动

```css
html {
  transform-origin: 0 0;      /* 必须是 0 0，锚点数学才成立 */
  transform: scale(k);
  overflow-anchor: none;      /* 放大期间关闭滚动锚定 */
}
```

`transform` 只进入绘制/合成阶段，**不进入布局阶段**，所以零次重排。
根元素带 transform 后 `scrollWidth/scrollHeight` 会按倍率自动放大，
滚动条天然可用——**不需要任何 `width: 200%` 之类的补丁**（加补丁才是真的改布局）。

### 锚点补偿（让鼠标下的那一点钉死）

```js
d = (scrollLeft + clientX) / k        // 鼠标下那个「未缩放文档坐标」
scrollLeft' = d * k' - clientX        // 换新倍率后让它回到同一个屏幕像素
```

每帧都用 `d` 重新计算，**不在当前滚动值上做增量**，所以零累计误差，滚一百次也不漂。

两个容易踩的坑，这里都躲开了：

- **滚动值不取整。** 取整每格引入 0.5px 误差，连滚几十格会累积成肉眼可见的漂移。
  小数滚动量是安全的：Chromium 绘制时会把合成层对齐到整数设备像素，文字不会发虚。
- **倍率做浮点吸附。** `1 / 1.12 * 1.12` 在浮点下不严格等于 1，不吸附就会卡在
  `1.0000000000000009`，退出判定只能靠容差兜。

### 性能设计

| 阶段 | 开销 |
|---|---|
| 平时（未按 Alt） | 1 个 `passive` wheel + 1 个 keydown，非 Alt 立即 return。零样式写入、零合成层、零 rAF |
| 按住 Alt 期间 | 才挂上非 passive 的 wheel（为了 `preventDefault` 阻止页面滚动）；非 passive 监听器只在此刻存在，所以平时滚动的合成器快路径不受影响 |
| 缩放过程 | `requestAnimationFrame` 合并同一帧的多次滚轮事件，指数逼近（约 110ms 收敛），只要指针不移动就只重绘不重排 |
| 退出 | 所有内联样式按保存的原值**逐条精确还原**（含 `priority`），不派发任何事件，HUD 节点销毁 |

## 十、遇到问题怎么反馈

把下面两样发出来，定位会非常快：

1. **诊断报告**：在出问题的页面上点「载入扩展级检测」（或网址加 `?magDiag=1`），
   按住 <kbd>Alt</kbd> 滚轮放大、松手，然后把控制台里 `[ALT Magnifier 检测]` 开头的那段贴出来。
   它会列出**哪些元素位移了多少像素**以及它们的 `position` / `background-attachment`。
2. **调试日志**：设置页打开「调试日志」，在页面控制台看 `[ALT Magnifier]` 输出。

拿到这两样，就能判断是「真位移」「尺寸畸变」还是「站点自身 JS 在重算」。
